## A.2 Доделано в этот день

1. **Длительность обязательна для Single** (`required` + звёздочка); для Series обязательны
   число серий и минуты на серию. Проверено: пустая длительность блокирует сохранение.
   Побочный эффект: старые проекты без длительности нельзя сохранить, пока её не впишут.
2. **Format убран из админки по-настоящему.** Поля не было, но сервер читал `format` из формы —
   то есть **каждое сохранение стирало колонку** и вместе с ней чип формата в каталоге. Убрано
   из обработчика; проверено на проекте №35 — значение сохранилось. Плюс Single с длительностью
   теперь сам формирует «95m» (раньше это умели только сериалы).
3. **Budget** — подпись «Budget (AMD, optional)» вместо «Budget (box office, AMD)».
4. **MP4 не загружался — найдена настоящая причина.** Не лимит Server Actions (он был 52 МБ), а
   `proxyClientMaxBodySize`: поскольку в проекте есть `src/proxy.ts`, Next буферизует копию тела
   запроса с лимитом **10 МБ** и молча обрезает всё выше — парсер падал с
   «Unexpected end of form» → 500, а в окне загрузки **не появлялось никакого сообщения**.
   Сделано: лимит поднят до 52 МБ; ошибка загрузки теперь видна; размер проверяется до отправки
   (50 МБ видео / 8 МБ картинки); подпись «MP4 / WebM · ≤50 MB»; отдача видео с byte-range (206,
   потоком) — перемотка работает, 50-мегабайтный файл не читается в память целиком.
   Проверено загрузками 0.8 / 1.4 / 2.4 / 6 / 10 / 13.7 / 44.5 МБ — прошли; 55.6 МБ отклонён с
   понятным сообщением.
5. **Картинки 16:9 крупнее**: постер и галерея 224 px вместо 160; плитки медиатеки были
   квадратные (обрезали кадр) — стали 16:9 и крупнее.
6. **Cast & Crew — только роли.** Выпадающий список «Cast/Crew» убран и в форме проекта, и в
   справочнике `/admin/cast`; категория выводится из роли (Director/Writer/Producer → Crew,
   Actor/Host/Singer → Cast). Старые свободные роли сохраняют свою категорию — правка не
   переворачивает существующих членов группы.
7. **Подсказка под «Production stage» убрана** (ключ в словаре оставлен).

Проверки: типы чистые, тесты **142 проходят** (добавлены на вывод категории по роли и на
byte-range), прод-билд собирается локально (`exit 0`) — то есть на Hostinger молча не упадёт.

## 6. Сверка с CSV-схемой заказчика

Реализовано практически всё; расходится **обязательность** и семантика двух полей.

**Требуется по CSV, но никто не проверяет:** Studio Name, Release Date, Longline/Short info
(tagline), Placement Name и Placement Description, «хотя бы один пакет размещения». Серверная
проверка ограничена названием, жанром и синопсисом (`projects/actions.ts:213-218`).

**Смысловая подмена:** CSV просит **Budget** (бюджет производства), в системе поле
`boxOfficeAmd` — **кассовые сборы** (`schema.prisma:164`). Это разные вещи, и на витрине
показываются сборы.

**Не реализовано:** картинка в строке «Past Projects» (CSV допускает ссылку или изображение —
есть только ссылка); «Expected Release Date» — см. 1.5.

**Сверх CSV:** язык, кинотеатры, тип размещения, маркетинговый формат, Production Timeline,
группировка каста и мульти-роли со справочником персон, видимость, модерация, порядок
сортировки, общее число слотов.

## 7. Цифры на дашборде считаются не по подписи

`admin/(panel)/page.tsx:22-27`:
- «Projects — in catalog» считает **все** проекты в базе, без фильтра по активности и модерации;
- «Users — admins & publishers» считает **всех** пользователей, включая бренды и создателей;
- для модератора карточка «your projects» всегда `0` — он не владеет проектами.
