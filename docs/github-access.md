# Как дать Адаму доступ к репозиторию

Репозиторий: **`XxHaykxX/Advertising-Platform`**
Ссылка: https://github.com/XxHaykxX/Advertising-Platform

---

## Сначала — нужен ли доступ вообще

Для того, что делает Адам (заводит сервер на Amazon), **доступ к коду не нужен**.
Ему нужна ровно одна строка, чтобы Amazon пускал выкатку только с нашего репозитория
и ни с какого другого:

```
repo:XxHaykxX/Advertising-Platform:*
```

Эту строку он впишет в настройку доверия на своей стороне. Всё. Можно просто отправить
её сообщением.

Доступ имеет смысл давать, только если Адам будет **сам смотреть**, почему выкатка не
прошла. Тогда — чтение, не больше (см. ниже, почему).

---

## Доступ по email дать нельзя

Это ограничение GitHub, не наше. В личный репозиторий соавтора добавляют **только по имени
пользователя** на GitHub. Приглашения по email работают у организаций, у нас не тот случай.

**Спроси у Адама его username на GitHub** — короткое имя из адреса его профиля,
например `github.com/adam-something` → `adam-something`.

---

## Как дать доступ на чтение

1. Открой https://github.com/XxHaykxX/Advertising-Platform
2. Вкладка **Settings** (шестерёнка, справа в ряду вкладок)
3. Слева в меню — **Collaborators**
4. Кнопка **Add people**
5. Введи **username** Адама (не email), выбери его из списка
6. В поле роли выбери **Read**
7. **Add … to this repository**

Адаму придёт приглашение на почту. Пока он его не примет — доступа нет.

---

## ⚠️ Почему именно Read, а не Write

Запись в ветку `main` **автоматически выкатывает живой сайт**. Не «когда-нибудь потом» —
сразу. Любой случайный коммит уходит клиентам.

Read решает задачу «посмотреть, почему упало» полностью, и не создаёт этого риска.

Если позже понадобится больше — роль меняется в том же списке в два клика, и это обратимо.

---

## Как забрать доступ обратно

Там же: **Settings → Collaborators**, справа от имени — **Remove**.
Действует сразу.

---

## Если Адам предложит переехать на Bitbucket

Ответ по существу: на подготовку сервера это **не влияет никак** — Amazon всё равно,
где лежит код.

Но у нас с GitHub связаны три работающие вещи, и их придётся переписать:

1. **Выкатка на Amazon** — написана под GitHub, для Bitbucket нужна другая
2. **Кнопка «Опубликовать» у Мариам** в редакторе переводов — она пишет файл переводов
   напрямую через GitHub. На Bitbucket просто перестанет работать, пока не переписана
3. **Текущая выкатка на Hostinger** — живой сайт сейчас обновляется из GitHub

Поэтому: если переезжать — **после** переезда на Amazon, отдельной задачей. Иначе два
переезда наложатся, и при поломке будет непонятно, какой из них виноват.
