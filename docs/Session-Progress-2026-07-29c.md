## A1 — кнопка заявки на каждой карточке + липкая полоса

- `src/lib/offer-value.ts` (новый) — `offerValue`/`parseOfferValue` переехали сюда из

  при монтировании, проверяется по списку офферов проекта, попап открывается на нужной карточке,
  параметр стирается из URL через `replaceState`.
- `offer-apply-button.tsx` (новый) — бренд открывает попап, гость уходит на
  `/login?from=/reports/34?offer=P:5` и возвращается, создателю/стаффу и в архиве кнопки нет.
- `sticky-offer-bar.tsx` (новый) — «Размещение от {min} · N из M свободно» + кнопка. Появляется
  когда `#overview` ушёл из вида, прячется когда виден футер и пока открыт попап. Отдаёт свою
  высоту в `--offer-bar-h`, push-промпт (`push-subscribe.tsx`) на неё поднимается.
- `TierDTO.priceAmd` добавлен (сырые AMD) — сводке нужно сравнивать тиры с плейсментами.

## Ревью батча (2 агента) и что по нему исправлено

**HIGH — заявка одна на пару бренд↔проект.** `Interest` уникален по `(brandId, projectId)`, а
`submitApplication` делает `upsert`. Батч повесил кнопку на каждую из 9 карточек и намеренно не
меняет её вид после отправки → клик по второй карточке ПЕРЕЗАПИСЫВАЕТ заявку: плейсмент
меняется на пакет, бриф и сообщение стираются, `ACCEPTED` откатывается в `SENT`,
`respondedAt`/`responseNote` обнуляются, забронированный слот возвращается в пул.
**Сделано:** попап предупреждает («по этому проекту у вас уже есть заявка, отправка заменит её»)
— `apply.replaceWarning`. **Не сделано и требует твоего решения:** структурно правильно — снять
`@@unique([brandId, projectId])` и вести заявку на КАЖДЫЙ оффер отдельно
(`@@unique([brandId, projectId, tierId, placementId])`), переписав ответ создателя и отзыв
заявки на конкретную строку. Это миграция прод-БД и переделка потока ответов — в этот батч не
брал.

Остальное исправлено здесь же:
- скрытая липкая полоса оставалась в tab-порядке → `inert`;
- ссылка «Зарегистрироваться» на логине теряла `?from=` → гость, кликнувший заявку и ушедший в
  регистрацию, падал в кабинет без оффера. Теперь `from` идёт через регистрацию,
  `safeMemberRedirect` вынесен в `member-paths.ts` и стал общим для входа и регистрации;
- `safeMemberRedirect` не отбивал `..` (`/reports/../admin/i18n` браузер нормализует) → отбивает;
- чеклист говорил «всё заполнено» там, где публикация откажет: добавлены пункты «Студия» и
  «Хронометраж», пакет без списка выгод больше не считается заполненным (зеркалит
  `publishBlockers()`), список пунктов 15 → 17, тестов 204 → 206;
- сводка могла напечатать «14 из 11 свободно» — `availableSlots` зажат по `totalSlots`;
- `?offer=` вычищался из URL только для бренда → теперь для всех;
- таймлайн: `measure` на каждом событии scroll делал forced reflow по всем узлам → rAF-троттл;
  прыжок по точке уважает `prefers-reduced-motion`;
- ru «{n} серий» давало «1 серий»/«3 серий» → «{n} эп. × {m} мин», заодно сошлось с
  `FORMAT_TOKENS` («ep» → «эп»), где раньше было расхождение;
- бейдж в админке дублировал строки словаря текстом → читает `completeness.badge*` через
  `makeUI("en")`, чтобы правка Мариам в `/admin/i18n` не разъезжалась с копией;
- мёртвый ключ `projectForm.offer.noImage` подключён: иконка «нет картинки» в свёрнутой карточке
  получила доступное имя.

Не брал (не наш батч, разное): `useCollapsed` в `offer-card.tsx` раскрывает карточки после
form reset; `handleApply` в `media-crop-dialog.tsx` без `catch`.

Отдельно проверено ревьюером: подмена оффера через `?offer=` невозможна — сервер
перепроверяет принадлежность (`brand/actions.ts`, `findFirst({ id, projectId })`); N+1 в списках
нет; старых импортов `offerValue` не осталось.

Мелочь, оставленная как есть: после отправки заявки `revalidatePath` возвращает `?offer=` в
адресную строку (router пере-синхронизирует URL после `replaceState`). Косметика — попап уже
закрыт, повторный вход показывает предупреждение о замене.
