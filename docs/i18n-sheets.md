# i18n ↔ Google Sheets: цикл работы контент-райтера

Все тексты интерфейса сайта (775 ключей × hy/ru/en) живут в `src/lib/i18n.ts`.
Райтер правит их в Google-таблице; скрипты гоняют данные туда-обратно.
Google API и ключи не нужны — импорт идёт по публичной CSV-ссылке листа.

## Разовая настройка

1. Создать Google-таблицу. Доступ: «Все, у кого есть ссылка» → **Читатель**;
   райтера добавить **Редактором** по email.
2. `npm run i18n:export` → появляется `i18n-export.csv` (гитигнорен).
3. В таблице: Файл → Импорт → Загрузка → выбрать CSV → «Заменить текущий лист».
4. В `.env` добавить CSV-ссылку листа (НЕ обычную ссылку на таблицу):

   ```
   I18N_SHEET_CSV_URL=https://docs.google.com/spreadsheets/d/<ID>/export?format=csv
   ```

   `<ID>` — длинный код из адреса таблицы. Если нужный лист не первый,
   добавить `&gid=<gid листа>`.

## Рабочий цикл

1. Райтер правит колонки `hy` / `ru` / `en` прямо в таблице.
2. Владелец жмёт кнопку: GitHub → вкладка **Actions** → workflow
   **«i18n sync — pull translations from Google Sheet»** → **Run workflow**.
   Дальше всё само: workflow скачивает таблицу, валидирует, точечно
   переписывает изменённые ключи в `src/lib/i18n.ts` (дифф минимальный,
   секционные комментарии сохраняются), гоняет `tsc` + тесты и, если что-то
   реально изменилось, коммитит и пушит в `main` — дальше Hostinger
   подхватывает пуш автодеплоем сам. Ручных шагов нет.
   - Если в таблице ошибка (пустая ячейка, потерянный плейсхолдер, гомоглиф,
     удалённая/добавленная строка, изменённый `key`) — workflow падает
     красным на шаге импорта, ничего не коммитит; список проблем — в логе
     шага. Правим таблицу и жмём Run workflow ещё раз.
   - Если правок не было (таблица уже совпадает со словарём) — workflow
     зелёный, но коммита не будет: в логе шаг «no changes».
3. Запасной путь (без GitHub, руками, например при отладке): локально
   `npm run i18n:import` (берёт ссылку на таблицу из `.env`), затем
   `npx vitest run` + `npx tsc --noEmit`, затем commit + push в `main`.

Настройка секрета `I18N_SHEET_CSV_URL` для workflow (один раз): GitHub →
Settings репозитория → Secrets and variables → Actions → New repository
secret → имя `I18N_SHEET_CSV_URL`, значение — та же CSV-ссылка, что и в
`.env` (см. «Разовая настройка» выше).

## Памятка райтеру (вставить в шапку таблицы или отправить письмом)

- Править можно **только** колонки `hy`, `ru`, `en`.
- Колонку `key` не менять, строки не удалять и не добавлять.
- Слова в фигурных скобках — `{n}`, `{name}` — это подстановки: не переводить,
  не удалять, оставлять как есть в любом языке.
- Пустых ячеек не оставлять.
- В армянский текст не вставлять русские буквы (частая ошибка при копипасте —
  русская «о»/«а» вместо армянской буквы; импорт такое отловит и укажет ключ).

## Когда разработчики добавили новые ключи

Новые ключи появляются в таблице **сами**, без ручного экспорта/импорта CSV.

В таблице есть отдельный служебный лист (например «🔒 Новые ключи»,
только для чтения — райтер его не правит, там всего одна формула в ячейке
`A1`):

```
=IMPORTDATA("https://igovazd.am/api/i18n/export.csv")
```

Google сам подтягивает эту ссылку каждые ~час (или по кнопке
«Обновить» / пересчёту формулы). Ссылка отдаёт живой словарь текущего
билда сайта — как только новый ключ появляется в `src/lib/i18n.ts` и
деплоится, он тут же виден на служебном листе.

Перенос нового ключа со служебного листа на рабочий (тот, что правит
райтер) — руками, копипастом:

1. На служебном листе найти новую строку (ключа, которого ещё нет на
   рабочем листе, — обычно внизу).
2. Скопировать всю строку (`key`, «Где на сайте», `hy`, `ru`, `en`).
3. Вставить строку в конец рабочего листа.
4. Сказать райтеру, что появилась новая строка для перевода.

Строки, которые уже есть на рабочем листе, на служебном листе повторно
трогать не нужно — он только для того, чтобы **заметить** новые ключи.

## Что НЕ входит в таблицу

- Контент из БД: названия и синопсисы проектов, портфолио — редактируются
  в админке, там уже есть поля для всех трёх языков.
- Одноязычные поля БД (студия, tagline, названия партнёров) — пока без i18n.
- Тексты админ-панели — она намеренно англоязычная.

## Файлы

- `scripts/i18n-export.ts` — словарь → `i18n-export.csv` (ручной разовый экспорт)
- `scripts/i18n-import.ts` — Google Sheet → `src/lib/i18n.ts`; URL берёт из
  `process.env.I18N_SHEET_CSV_URL` (так работает в GitHub Actions), а если
  переменной нет — падает назад на чтение `.env` (локальный запуск)
- `src/lib/i18n-csv.ts` — чистые (без `node:fs`) CSV-хелперы: заголовок,
  карта контекстов, сериализация/парсинг, проверки. Используются и скриптами
  (через `scripts/i18n-lib.ts`, который их просто реэкспортирует), и роутом
  ниже
- `src/app/api/i18n/export.csv/route.ts` — публичный (без авторизации) роут,
  отдаёт тот же CSV, что и `npm run i18n:export`; на него смотрит служебный
  лист таблицы через `IMPORTDATA`
- `.github/workflows/i18n-sync.yml` — кнопка **Actions → Run workflow**:
  импорт → tsc → тесты → commit+push, если что-то изменилось
- Финальная защита: `src/lib/i18n.guard.test.ts`
