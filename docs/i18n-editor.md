# i18n: редактор переводов в админке

Все тексты интерфейса сайта (855 ключей × hy/ru/en) живут в `src/lib/i18n.ts`.
Райтер правит их **прямо в админке** — `/admin/i18n`, роль `TRANSLATOR`. Google-
таблица, которая раньше была источником правды, теперь архив (см. «Почему
таблица ушла в архив» ниже) — синк из неё отключён.

## Как это работает

1. Райтер логинится на `/admin/login` под ролью `TRANSLATOR`. У этой роли нет
   доступа никуда, кроме `/admin/i18n` (нет Dashboard, нет других разделов
   нав-панели — `src/lib/auth/permissions.ts`: `canEditTranslations`,
   `isTranslatorOnly`), и вход сразу ведёт туда.
2. В редакторе правит `hy` / `ru` / `en` по каждому ключу, может поставить
   цветную метку и оставить заметку — прямая замена цветной заливки строк,
   которую райтер раньше делал в Google-таблице (`UiDraft.mark`):

   | Метка | Смысл |
   |---|---|
   | 🟢 зелёная | проверено, финально |
   | 🔴 красная | проблема / нужно решение |
   | 🔵 голубая | в работе, вернуться позже |
   | без метки | не трогали |

   По меткам есть фильтры — можно, например, показать только красные строки.
3. Кнопка **«Сохранить»**: досылает на сервер всё, что ещё не ушло (правки и
   так автосохраняются в черновики с задержкой — кнопка нужна, чтобы не
   ждать), и показывает сообщение «Сохранено: N ключей» или «Всё уже
   сохранено». Сообщение не исчезает само — у него есть крестик «закрыть».
   Зелёная отметка «сохранено» у самой строки гаснет через пару секунд.
4. Кнопка **«Опубликовать»**: сервер валидирует правки (см. ниже), точечно
   переписывает изменённые ключи в `src/lib/i18n.ts` и коммитит файл в `main`
   через GitHub Contents API (`src/lib/github/contents.ts`). Показывает
   «Опубликовано: N ключей» со ссылкой на коммит; сообщение висит до
   завершения сборки на Hostinger («опубликовано, ждёт сборки»), а не гаснет
   само. Недоступна, если нет неопубликованных правок или не задан
   `GITHUB_SYNC_TOKEN`.
5. Коммит в `main` = пуш → Hostinger подхватывает автодеплоем сам
   (~5 минут на пересборку). **После публикации обязательно проверять, что
   сборка на Hostinger реально завершилась** — билд может молча упасть, и
   прод продолжит отдавать старую версию (`docs/DEPLOY-PLAYBOOK.md`, раздел
   «После push»).

GitHub Actions в цикле больше нет — правка → валидация → коммит → деплой идёт
из кнопки «Опубликовать» на странице редактора. Экспорт/импорт CSV остался, но теперь это опция для тех, кому
удобнее работать в Excel, а не обязательный шаг: «Скачать CSV» отдаёт текущее
состояние словаря вместе с метками и заметками; «Загрузить CSV» сначала
показывает превью («будет применено N ключей, пропущено M неизвестных») и
только после подтверждения заносит правки в черновики — сразу с диска ничего
не публикуется.

## Эргономика таблицы

Табличный вид с закреплённой шапкой и колонкой ключа (длинная таблица не
теряет ориентиры при прокрутке), компактный/обычный режим строк, сворачиваемые
группы по разделам сайта. Навигация с клавиатуры: `Tab`/`Enter` — на строку
ниже, `Shift+Enter` — перенос строки внутри ячейки, `Esc` — откат правки в
текущей ячейке, `Ctrl+S` — сохранить всё. Кнопка рядом с ячейкой копирует
значение из одного языка в другое (например, чтобы не перепечатывать `en`,
если `ru` уже совпадает).

### Undo / Redo

Кнопки «Назад» и «Вперёд» в панели действий + горячие клавиши `Ctrl+Z`
(назад) и `Ctrl+Shift+Z` / `Ctrl+Y` (вперёд). В историю попадают: правка
значения, смена цветной метки, правка заметки, «вернуть как в коде» и
применение CSV-импорта (весь импорт — один шаг). Правки одной ячейки
склеиваются в один шаг истории. История — до 100 шагов, живёт до перезагрузки
страницы (в `sessionStorage`/памяти вкладки не переживает). Откат и повтор
так же сохраняются в черновики, как обычная правка.

### Бесконечный скролл

Пагинации нет — строки подгружаются по мере прокрутки порциями по 50. Над
таблицей — счётчик «Показано N из M» и кнопка «Показать все» (нужна, если
хочется искать по всей таблице через `Ctrl+F` браузера, а не только по уже
подгруженным строкам).

## Что нужно в env

- `GITHUB_SYNC_TOKEN` — fine-grained PAT на репозиторий
  `XxHaykxX/Advertising-Platform` с правом **Contents: Read and write**.
  Без него кнопка «Опубликовать» падает с ошибкой «GitHub-токен не
  настроен».
- `GITHUB_SYNC_REPO` (опционально) — если репозиторий переедет, иначе по
  умолчанию `XxHaykxX/Advertising-Platform`.
- `GITHUB_SYNC_BRANCH` (опционально) — целевая ветка коммита, по умолчанию
  `main`.

Как и остальные секреты проекта — только в `.env` (локально) и в hPanel Node.js
app config (прод), не коммитятся (`AGENTS.md`).

## Валидация

Перед коммитом сервер проверяет каждую правку и отклоняет весь сейв, если
что-то не так (список проблем — по ключам, в ответе редактора):

- пустые ячейки — каждый ключ должен быть переведён на все три языка;
- гомоглифы в армянском — русские «о»/«а» и т.п. внутри армянского слова
  (частая ошибка при копипасте, буквы почти неотличимы на глаз);
- плейсхолдеры вида `{n}`, `{name}` — должны присутствовать в неизменном
  виде в переводе на каждый язык, где встречаются в оригинале.

## Почему таблица ушла в архив

Google-таблица была временным решением, пока не было своего редактора: она
не умела хранить цветную метку и заметку к ключу иначе как заливкой ячейки и
комментарием, которые терялись при экспорте/импорте CSV. В редакторе это —
обычные поля (`UiDraft.mark`, `UiDraft.note`), которые едут вместе с переводом
и переживают «Скачать CSV» / «Загрузить CSV» без потерь. Отдельно остаётся
публичный `/api/i18n/export.csv` (см. ниже) — как бэкап и для быстрого обзора
всего словаря без захода в админку; он отдаёт только `hy`/`ru`/`en`, без
меток и заметок, и не участвует в загрузке правок обратно.

## Инструкция для райтера

`docs/i18n-writer-guide.md` — нетехническая инструкция для контент-райтера
(на английском): как войти, как работать со страницей Translations, что
значат красные подсказки. Без упоминания GitHub/PAT/Prisma.

## Файлы

- `src/app/admin/(panel)/i18n/*` — страница редактора и его server actions.
- `src/lib/i18n-csv.ts` — чистые (без `node:fs`) CSV-хелперы: заголовок,
  карта контекстов, сериализация/парсинг, проверки. Использует и роут ниже.
- `src/app/api/i18n/export.csv/route.ts` — публичный (без авторизации) роут,
  отдаёт CSV-снапшот текущего словаря; бэкап/обзор, в цикл правок больше не
  завязан.
- `src/lib/github/contents.ts` — коммит `src/lib/i18n.ts` в `main` через
  GitHub Contents API.
- `src/lib/auth/permissions.ts` / `src/lib/auth/require.ts` — роль
  `TRANSLATOR`, `canEditTranslations`, `requireTranslator`.
- Финальная защита: `src/lib/i18n.guard.test.ts`.
