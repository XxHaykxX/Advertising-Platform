## Решения владельца, зафиксированные в коде

1. **Код проекта** (#PP-…) — виден только в админке. В публичном каталоге и в обоих
   кабинетах скрыт; поле убрано и из DTO кабинетов.
2. **«Production stage»** — убрано из админ- и creator-формы вместе с подсказкой.
   Колонка `Project.status` осталась: фильтр каталога и страница проекта её читают.
   Поле убрано и из разбора формы, иначе каждое сохранение писало бы
   «Пре-продакшен» поверх реального значения.
3. **Сделку ведёт владелец проекта.** Штат видит все заявки в `/admin/interests`,
   но «Принять/Отклонить» появляются только на своих проектах; серверный экшен
   проверяет владельца независимо от роли.
4. **Обязательные поля** блокируют публикацию, а не сохранение — и только на
   переходе в публикацию (создание активного проекта, включение галочки «Активен»,
   одобрение модератором). Уже опубликованный проект правится свободно.
5. **Медиатека**: папка `videos` принимает только MP4/WebM, остальные — только
   изображения; `references` принимает и то и другое. Проверяется и на сервере.

## Грабли, которые стоили времени

- **publishGate нельзя вешать на любое сохранение активного проекта** — первая
  версия блокировала правку уже опубликованных карточек.
- **Тиры нельзя пересохранять через delete+create**: на них ссылается
  `Interest.tierId` и висит резерв слотов. Теперь update по `dbId`.
- **Повторная заявка возвращала слот не тому пакету** — состояние заявки надо
  читать ДО upsert.
- **Серверный компонент не может импортировать функцию из `"use client"` модуля** —
  типы и билд молчат, падает только при открытии страницы.
- **Админка English-only**: `getLocale()` в админ-странице даёт армянские заголовки
  внутри английской панели.
- **Список с локальной копией строк** (`useState(props)`) не обновляется после
  серверного revalidate — удалённый проект висел до перезагрузки.
