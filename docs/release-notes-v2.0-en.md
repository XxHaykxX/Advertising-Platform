Release v2.0 — July 26, 2026

What's new and what's fixed on igovazd.am.

— Brand offers —
1. The section is no longer called "Applications". A brand does not apply to be accepted — it arrives with money and names a package — so it is now "Brand offers", and "My offers" on the brand's side. The old name also clashed with the two other things called applications: project submissions and account approvals.
2. A brand's offer now carries a brief: what is being placed, the preferred timing, and whether the offer is cash, barter or both. All three are optional, but they are asked for, so the seller no longer has to guess from one paragraph of prose.
3. The seller sees the brand's budget bracket and its categories. Both were filled in when the brand registered and, until now, read by nobody — the decision on a package worth millions was made from a name and an email address.
4. A phone number is now required with every offer, checked as a real international number. Armenian numbers must be exactly eight digits after +374, so a typo is caught instead of becoming a lead nobody can call back. The field starts on +374.
5. If the account already has a phone on file, the popup stops asking for it and simply shows the number. The free-text "Contact" box is gone with it — it only asked again for what the account already knows.
6. An offer must actually say something: a one-word message is no longer accepted.
7. The brand's own cabinet finally shows what it sent — the request used to be invisible to both sides, so a brand with several offers could not tell which terms it had proposed where.
8. Offers can now be answered by a super-admin as well as by the project's owner. Answering was tied to the exact owner of the project, which meant that once projects belong to creators nobody on the platform side could reply at all, and an offer sat unanswered if the creator went quiet.
9. An offer can only be sent to a published project. It was previously possible to aim one at a project still awaiting moderation or already taken off the catalog.
10. The brief is kept per round in the history, so resending an offer with new terms no longer overwrites what was originally proposed.
11. The email announcing a new offer now carries the brief and the brand's budget, so a lead can be judged without opening the cabinet.

— Moderation and projects —
12. Projects waiting for a decision no longer sit in the Projects list looking like ordinary switched-off projects. They stay in Moderation until approved, and a line above the list shows how many are waiting.
13. The "N in catalog" count now counts what is really in the catalog, and says separately how many projects are approved but unpublished.
14. Clicking a project's name opens the project as visitors see it, in a new tab, instead of dropping you into the edit form. Editing is a separate, deliberate click. This applies in the offers section, the projects list and the moderation queue.
15. Approve is now blue and Reject is red, each with an icon, plus a View button with an eye icon to read a submission before judging it.
16. Every staff role can open a project that has not been approved yet — including the translator, who used to get a "not found" page for the very texts she is meant to check.
17. Creators can open their own project in any status. They wrote it, and after a rejection the one thing they need is to see what they sent.
18. The internal project code is no longer shown anywhere in the interface.

— Notifications —
19. The offers section now shows how many offers are waiting for an answer, both in the admin panel and in the creator's cabinet. An offer used to arrive with no visible sign at all.
20. The count also refreshes when you come back to the tab, not only when you move between sections — which is exactly when someone is watching for new arrivals.
21. Staff can now switch on browser notifications. The option existed only in the member cabinets, so a notification addressed to an administrator had nowhere to go.
22. If the browser has blocked notifications, the site now says so and explains where to allow them. It used to stay silent, and the account simply stopped hearing about anything.

— Fixes —
23. Cancelling no longer confirms. Dismissing the box that asks for a message used to send the answer anyway — accepting an offer, or rejecting a project, could not be taken back, even though it changes the status, books the package slot and emails the other side.
24. All the browser's own grey dialog boxes are gone. Accepting or declining an offer, writing a rejection reason, deleting a partner, a case study or a streaming platform — each now opens a proper window in the site's own design, with room to write a real message.
25. The Delete button in confirmation windows is red. It was blue, so a destructive action looked like any other.
26. Internal improvements to security, checks and performance.
