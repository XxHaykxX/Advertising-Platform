# Журнал сессии 2026-08-02 — «Create member» рапортовал ошибку об успешном создании

Короткая сессия, один баг + сплошной аудит его класса по всему репозиторию.
**Не выкачено** — правка лежит в рабочем дереве, прод остаётся на `df3dffa`.

## 1. Баг

Владелец: в админке после «Create member» показывается «Что-то пошло не так», **но аккаунт
при этом создан**.

Корень — `createMember` в `src/app/admin/(panel)/users/actions.ts` заканчивался
`redirect("/admin/users")` прямо в Server Action. `prisma.user.create` к этому моменту уже
отработал, дальше `redirect()` бросает `NEXT_REDIRECT`, Next отвечает на POST кодом 303 плюс
RSC-payload страницы-назначения, клиент на нём спотыкается и рисует error boundary
`src/app/admin/(panel)/error.tsx` — тот самый экран «Что-то пошло не так».

Это ровно тот дефект, который в проекте уже лечили дважды (чёрный экран 15.07 в форме
проектов, партнёры и портфолио 30.07). Контракт зафиксирован комментарием в
`src/app/admin/(panel)/partners/actions.ts:65` — «почему эти действия возвращают
`{ ok, redirect }` вместо вызова `redirect()`». В форму пользователей его когда-то не
перенесли.

## 2. Фикс

Тот же контракт, что во всех остальных формах приложения:

| Файл | Правка |
|---|---|
| `src/app/admin/(panel)/users/actions.ts` | `FormState` получил `ok?` + `redirect?`; `createMember` теперь `return { ok: true, redirect: "/admin/users" }`; импорт `redirect` из `next/navigation` убран |
| `src/app/admin/(panel)/users/user-form.tsx` | `useEffect` на `state.ok && state.redirect` → `window.location.assign(...)`; кнопка «Create member» остаётся заблокированной после успеха |

Кнопка не разблокируется после успешного создания намеренно: навигация — полная
перезагрузка страницы, и без этого кнопка на мгновение снова живая, а второй клик упал бы
на дубликате email.

⚠️ `useEffect` завязан на `[state]` целиком, а **не** на `state.ok` — ловушка IA-15: два
успешных сохранения подряд читаются одинаково, а `useActionState` отдаёт новый объект на
каждый dispatch. Так же сделано в `partner-form.tsx:44` и `portfolio-form.tsx`.

`npx tsc --noEmit` — чисто. Отдельных тестов на `/admin/users` в репозитории нет.

## 3. Аудит класса бага по всему репозиторию

По просьбе владельца («если в других местах то же самое — чини сразу») прочёсан весь `src`.
**Других экземпляров нет** — `createMember` был последним.

| Что проверял | Итог |
|---|---|
| `redirect()` / `permanentRedirect()` внутри всех 45 файлов с `"use server"` | Ни одного. Везде уже стоят комментарии «Don't redirect() here» — login, register, forgot, admin, account, history, portfolio, partners, projects |
| Потребители контракта `{ok, redirect}` на клиенте | Все 10 форм подключены к `window.location.assign` — никто не теряет редирект молча |
| `notFound()` в actions (тоже throw → тот же error boundary) | 6 вызовов, все стоят **до** записи, как guard. Ложной ошибки после успеха не дают |
| `router.push(res.redirect)` в `projects/row-actions.tsx:57` (дубликат проекта) | Оставлен намеренно — см. ниже |

`duplicateProject` вызывает `revalidateProjectPaths()` без `id`, а это `updateTag("projects")`
плюс `revalidatePath("/admin/projects")` — всё внутри ветки admin-layout, корневой layout не
пересевается, поэтому клиентская навигация роутером здесь не ломается. Обоснование записано
в `actions.ts:589-607`.

## 4. Урок

⚠️ **Опровергнуто прежнее «безопасное исключение».** После разбора 30.07 в заметках осталось,
что `redirect()` не ломается, если действие ревалидирует только свою ветку layout, и как
пример безопасного случая назывался как раз `users` → `/admin/users`. Этот баг показал
обратное: `createMember` ревалидировал ровно `/admin/users` и всё равно приводил к ошибке
на успешном создании. Исключения нет — правило действует **всегда**: никакого `redirect()`
внутри Server Action, только `{ ok, redirect }` + `window.location.assign`.

Механику 303-ответа именно для этого случая живьём на проде не снимали (симптом пришёл от
владельца, фикс сделан по контракту), так что утверждать «это тот же ChunkLoadError» нельзя —
достоверно только то, что успешная запись рапортовалась как ошибка, и уход от `redirect()`
эту развилку убирает.
