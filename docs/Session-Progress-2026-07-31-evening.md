страницах проектов не видно (имя и фото берутся из `Actor`), сломан был только справочник

## 3. История изменений контента с откатом

Причина: у `Project` не было даже `updatedAt`, поэтому 31.07 не удалось выяснить, кто
испортил проекты и куда делись три из них. Подробный план и решения владельца —
`docs/plan-content-history.md`.

Каждое сохранение пишет `ContentVersion`: снимок **всего агрегата** (проект + каст + тиры +
размещения + этапы) в JSON, поэтому откат возвращает всё разом.

- Ядро — `src/lib/history/`: `snapshot.ts`, `diff.ts`, `record.ts`, `restore.ts`.
- `/admin/history` — лента по всему сайту с фильтрами; подряд идущие правки одного автора в
  окне 15 минут склеиваются в одну разворачиваемую строку (склейка только для показа).
- `/admin/history/deleted` — корзина с восстановлением.
- Вкладка «История» на страницах проекта, кейса и партнёра.
- Смотрят все staff, откат — только SUPERADMIN. Версии хранятся все.

⚠️ **Версия пишется внутри той же транзакции, что и сохранение** — иначе история утверждала
бы об изменениях, которых не случилось. `recordVersion` намеренно не бросает исключений:
история не должна ронять сохранение.

⚠️ **Вкладка не размонтирует форму** — переключение прячет её классом `hidden`, а не
условным рендером. Иначе черновик в `project-form.tsx` терялся бы при клике по вкладке.

Не сделано: у `Person` нет своей страницы, ссылка ведёт на `/admin/cast` целиком; склейка
считается в пределах страницы выдачи.

## 5. Админка: роли, удаление аккаунтов, владелец

- **Смена роли сотрудника** — `src/lib/auth/staff-roles.ts` + `setUserRole`.
- **Удаление аккаунта** — `src/lib/auth/delete-account.ts`, кнопка на обеих вкладках.
- **Колонка Owner** показывает `User.company` (запасной вариант — имя); фильтр читает то же
  поле.

⚠️ **«Последнего суперадмина» считать ТОЛЬКО среди активных.** `requireUser()` отклоняет
`isActive=false` (`src/lib/auth/require.ts:61`), поэтому деактивированный владелец — не
замена. Агент сначала считал всех подряд: понизив единственного активного, можно было
запереть себя снаружи. Правило действует и для смены роли, и для удаления.

⚠️ **`Project.ownerId` — обязательная связь без правила удаления** (`schema.prisma:211`).
Владельца проектов удалить нельзя, база откажет на уровне FK. Проекты вместе с аккаунтом
НЕ удаляем — панель объясняет «owns N projects».

## 6. Фильтры и поле Format

⚠️ **Фасеты фильтров надо строить из фактических данных.** Format и Language разворачивали
весь закрытый список (12 форматов на каталог из 7 проектов). Теперь Format отбирает
присутствующие, сохраняя порядок `FORMAT_CATEGORY_VALUES` (он editorial, не алфавитный).
Genre и Platform так работали и раньше.

⚠️ **Поле Format было недоступно для правки.** При редизайне админки его убрали из формы,
оставив скрытым `input`, — значит фильтр каталога работал по полю, которым никто не
управлял. Возвращено как настоящий контрол в форму (её же переиспользует кабинет
создателя). Публикацию не блокирует: пустое значение по-прежнему выводится из жанра.

⚠️ **Поле `kind` было подписано «Формат»** — то же слово, что у настоящего Format. Отсюда
жалоба «в админке два формата, в витрине двенадцать». Переименовано в «Тип».

Format добавлен в чеклист «Что увидит бренд» (`src/lib/project-completeness.ts`). Отличие
от остальных пунктов: пустой раздел просто не рисуется, а пустой Format выкидывает проект
**из фильтра каталога целиком**.
