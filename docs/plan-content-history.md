# План: история изменений контента с откатом

**Статус:** ✅ реализовано 2026-07-31. Миграция на прод применена в тот же день (раньше кода —
понадобилась для заливки контента Kinodaran). Код ждёт общего деплоя вместе с удалением
стадии производства.
**Зачем:** 31.07 выяснилось, что по базе невозможно установить, кто и когда испортил
проекты, — у `Project` нет даже времени изменения. Три проекта пропали бесследно.
Для словаря переводов такая история есть (`I18nPublish` + коммит в git), для контента — нет.

## Решения владельца

| Вопрос | Решение |
|---|---|
| Глубина | Полные версии + откат кнопкой из админки |
| Охват | Весь контент: Project (с кастом, тирами, размещениями, этапами), Person, Portfolio, Partner |
| Удаление записи | Корзина с восстановлением — финальный снимок хранится, проект можно вернуть |
| Кто смотрит | Все staff-роли |
| Кто откатывает | Только SUPERADMIN |
| Сколько версий | Все, без автоочистки |
| Файлы из старых версий | Удалять можно, но с предупреждением, где именно файл используется — со ссылками |
| Переводы | Не дублируем: у словаря уже есть история через git |
| Порядок перетаскиванием | В историю не пишем — шум, а не изменение контента |

## Схема

```prisma
model ContentVersion {
  id         Int      @id @default(autoincrement())
  entity     String   @db.VarChar(32)  // Project | Person | Portfolio | Partner
  entityId   Int
  version    Int      // 1, 2, 3… в рамках entity+entityId
  action     String   @db.VarChar(16)  // CREATE | UPDATE | DELETE | RESTORE | PUBLISH | UNPUBLISH
  snapshot   String   @db.LongText     // полное состояние агрегата, JSON
  mediaPaths String?  @db.Text         // все /uploads/… из снимка — для поиска «где используется файл»
  summary    String?  @db.Text         // «описание (ru), постер» — какие поля изменились против прошлой версии
  authorId   Int?
  authorName String   @db.VarChar(191) // копия имени: переживает удаление аккаунта
  createdAt  DateTime @default(now())

  author User? @relation(fields: [authorId], references: [id], onDelete: SetNull)

  @@unique([entity, entityId, version])
  @@index([entity, entityId, createdAt])
  @@index([createdAt])
}
```

`snapshot` — `LongText`, не `Json`: нужен дешёвый `contains` при поиске путей к файлам,
и MariaDB на проде с JSON-функциями капризнее. `mediaPaths` — денормализация ради того же
поиска, заполняется при записи версии.

## Что в интерфейсе

**Вкладка «История» на странице записи.** Список версий: время, автор, действие, строка
изменений («описание (ru), постер»). Кнопки «Сравнить с текущей» и — для SUPERADMIN —
«Вернуть эту версию» с подтверждением, в котором перечислено, что именно изменится.

**Раздел «Удалённые».** Записи с последним действием `DELETE`: что, кто и когда удалил,
кнопка «Восстановить». Восстановление возвращает проект вместе с кастом, тирами,
размещениями и этапами, новым id, с пометкой в истории.

**Медиатека.** При удалении файла показываем, где он используется: отдельно текущие записи,
отдельно старые версии — с кликабельными ссылками на запись и версию. Удаление не блокируется,
но предупреждение явно говорит, что откат на эти версии даст битую картинку.

## Что осталось несделанным

- **Вкладка «История» внутри записи** (на странице редактирования проекта, человека, кейса,
  партнёра) — сейчас история доступна только общей лентой `/admin/history`. Лента умеет
  фильтровать по типу записи, так что дырки в функциональности нет, но одного клика со
  страницы проекта пока нет.
- **У `Person` нет отдельной страницы** — правится инлайн в `/admin/cast`, поэтому ссылка из
  истории ведёт на раздел целиком, а не на конкретного человека.
- **Склейка считается в пределах страницы** — серия правок, попавшая на границу
  постраничности, покажется двумя группами. Ничего не теряется, только отображение.

## Подводные камни

- **Прод — MariaDB, не MySQL 8.** Проверять миграцию на `mariadb:11`, не на MySQL.
- **`redirect()` в Server Action ломает прод** — откат и восстановление возвращают
  `{ok, redirect}`, переход делает клиент через `window.location.assign`.
- **Кэш витрины.** После отката звать `revalidateProjectPaths`, иначе страница будет отдавать
  старое до пяти минут.
- **Снимок каста ссылается на `Person`.** Если человека удалили из справочника, откат должен
  создать его заново по данным снимка, а не падать.
- **Размер.** Снимок проекта ~20–30 КБ. Тысяча правок по всем проектам — около 30 МБ,
  для текущих объёмов несущественно.
