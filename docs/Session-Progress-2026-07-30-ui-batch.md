## Часть 1. «Имя проекта не сохраняется» — два разных бага, оба не про сохранение

Жалоба звучала как «правлю имя, не сохраняется». Имя сохранялось всегда.

**Легаси-колонка `title` собиралась русский-первым.** `buildData` выводила её как
`titleRu || titleHy || titleEn`, а дефолтная локаль сайта — `hy`. Список админки рендерит
именно `title`, поэтому армянское переименование записывалось в `titleHy` и было невидимо
везде, где выводится `title`. Порядок перевёрнут на hy→ru→en (то же для `synopsis` и
`tagline`), списки админки, модерации и кабинета создателя читают локальные колонки напрямую
— чтобы строки, записанные старым билдом, тоже отображались верно. Бэкфилл на проде: 7
расходящихся строк → 0.

**Витрина отдавала протухшее.** `revalidateTag(tag, "max")` — это stale-while-revalidate:
следующему посетителю отдаётся СТАРОЕ, свежее тянется фоном. Воспроизведено на проде без
авторизации: два одинаковых curl подряд — первый старое, второй новое. Заменено на
`updateTag(tag)` (только из Server Action; в Route Handler бросит `E872`).

Комментарий в `revalidateProjectPaths` винил не ту причину чёрного экрана 15.07: лечило не
`{expire:0}`→`"max"`, а уход от `redirect()` внутри экшена. Флаг `pathWasRevalidated` и так
выставлялся соседним `revalidatePath`, так что переход на `updateTag` даёт нулевую дельту.

**Попутно:** приём/отклонение/отзыв заявки двигают `availableSlots`, а слоты запечены в
кэшируемых DTO каталога — инвалидации не было вовсе.

## Часть 2. «Что-то пошло не так» в партнёрах — четыре ложных следа

Сохранение партнёра на проде падало в error boundary. Локально не воспроизводилось ни в dev,
ни в прод-сборке. Исключены проверками: данные (прод = локально), две сборки одновременно
(12 замеров отпечатка — одна), кэш LiteSpeed/CDN (чистил), процесс Node (рестартил дважды),
мусор старых сборок на диске (добавил `prebuild` с очисткой `.next`, пересобрал — имена не
изменились), service worker (`public/sw.js` без `fetch`-обработчика).

**Настоящая причина** снята перехватом `fetch` в странице — обычный `network` показывает
только статусы, нужно было ТЕЛО ответа. Сохранение проходило (`POST → 303`), а в 303-теле
лежал RSC-payload всего дерева от публичного корневого layout со ссылками на невыпущенные
чанки → `ChunkLoadError` → error boundary. Триггер: действие живёт под layout админки, но
ревалидирует путь из другой ветки (`/about`, раньше `/`). Лечение — отказ от `redirect()`
внутри Server Action в пользу `{ok, redirect}` + полная навигация. Тот же контракт стоит в
форме проектов с 15.07; в партнёры и портфолио его не перенесли. Портфолио починено
превентивно (там же был ru-first вывод имени).

## Часть 4. Найдено при тестировании батча

**Дыра в контейнменте загрузок (предшествовала батчу).** `safeSegment` намеренно разрешает
точку, из-за чего строка `..` проходила фильтр нетронутой, а `path.join` её нормализует —
папка поднималась на уровень вверх. Для участника это запись в `uploads/members/`, внутри
раздаваемой по HTTP папки; локально корень — `public/uploads`, то есть прямо в `public/`.
Закрыто двумя слоями: сегмент из одних точек не проходит, и путь проверяется на принадлежность
корню перед записью. Дыра была и в старых серверных действиях, новый роут её унаследовал.

**Выход из аккаунта через меню в шапке (регрессия этой же сессии).** Диалог выхода вынесен
порталом в `body`, а меню закрывается по `mousedown` мимо себя — кнопки диалога стали для него
«мимо». Лечение на стороне диалога, а не меню: тем же приёмом пользуются переключатели валюты
и языка, мультиселект и редактор каста.

**«Save and leave» не сохранял вовсе** — запрос не покидал браузер. Кнопка была кнопкой
отправки формы, её же обработчик закрывал диалог, React успевает размонтировать кнопку до
выполнения отправки. Заменено на явный `requestSubmit()`.

**Браузер переспрашивал после подтверждённого ухода.** Защита `beforeunload` навешана по
условию `isDirty`; снятие флага — обновление состояния, а уход происходит в том же такте,
поэтому оставался висеть обработчик от предыдущей отрисовки. Признак ухода вынесен в ref
(читается в момент срабатывания). Мест с программным уходом три — все закрыты.
