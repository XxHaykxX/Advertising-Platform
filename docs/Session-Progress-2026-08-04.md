# Журнал сессии 2026-08-04 — новые требования к публикации, гид /for-creators, чистка колонок

✅ **Выкачено**, прод `dd61c1f`, релиз v2.6. Выкатка доехала за ~120 с, отпечаток чанков
сменился `09eece43` → `e232d8cb`. Обе миграции применены, смоук на живом сайте пройден.

Задача от владельца: «нужна отдельная страница, где показываем креаторам, что нужно
заполнять, какие данные нужны». В ходе разбора выяснилось, что список требований нигде
не зафиксирован, а часть требований в коде не отражает того, чего платформа на самом деле
ждёт от проекта — поэтому работа разрослась с одной страницы до пяти направлений.

## 1. Три уровня обязательности — то, чего нигде не было записано

Требования к проекту разложены по трём разным местам, и ни одно из них не имело имени:

| Уровень | Где живёт | Что блокирует |
|---|---|---|
| Обязательно | `validate()`, `src/app/account/projects/actions.ts:167` | сохранение формы |
| Нужно для публикации | `publishBlockers()`, `form-shared.ts:194` (зеркало — `BLOCKS_PUBLISH` в `src/lib/project-completeness.ts`) | отправку на модерацию и одобрение |
| Желательно | нигде | ничего; пустой блок просто не отрисуется бренду (`completeness.hint`) |

Эта таблица стала осью и новой страницы, и подсветки в форме.

## 2. Четыре новых требования к публикации

Добавлены в `publishBlockers()` и продублированы в `BLOCKS_PUBLISH`:

| Требование | Что было без него |
|---|---|
| Постер | карточка каталога — пустой прямоугольник |
| Формат (`formatCategory`) | проект **выпадает из фильтра «Формат»**, бренд его не видит, создатель об этом не узнаёт |
| Решение по дедлайну (дата **или** флаг «принимаем постоянно») | бренд не понимает, актуально ли предложение |
| Минимум один продакт-плейсмент | витрина без товара — при том что плейсмент и есть продукт площадки |

### Дедовщина для плейсмента

Прод-аудит показал: у **всех восьми** живых проектов ноль плейсментов. Требование в лоб
сделало бы весь каталог неодобряемым. Владелец выбрал вариант «только для новых»:

- `PLACEMENTS_REQUIRED_FROM = new Date("2026-08-05T00:00:00Z")` в `form-shared.ts`;
- `PublishCheckInput` получил `createdAt: Date | null` (`null` = проект создаётся прямо
  сейчас, освобождению не подлежит);
- `projectCompleteness()` считает `blocksPublish` для ключа `placements` по тому же
  правилу, иначе чеклист врал бы старым проектам.

Постер, формат и дедлайн **не** дедовщинные — по решению владельца. Дозаполнение прода
не делали.

## 3. Просвечивание незаполненных полей в форме

Владелец: «обязательно добавь функционал просвечивания, если не заполнено».

Чеклист «Что увидит бренд» показывает **сохранённое** состояние, поэтому первым реальным
сигналом был отказ при отправке. Теперь форма помечает пробелы на месте и вживую.

Механика (`src/app/admin/(panel)/projects/project-form.tsx`):

- `PublishGapContext` держит набор **якорей** (`field-…` / `sec-…`) — тех же, по которым
  уже прыгает чеклист. Поле подключается к подсветке просто тем, что у него есть
  `anchorId`; второго реестра имён полей заводить не пришлось.
- `recomputePublishGaps()` — зеркало `publishBlockers()`. Именно зеркало, а не общий
  импорт: та функция читает сохранённую строку БД, а эта — полузаполненную форму, где те же
  значения лежат в трёх разных местах (неконтролируемые инпуты, рефы за скрытыми
  языковыми вкладками, React-состояние репитеров).
- Вешается на тот же `onInput` формы, что и автосохранение черновика, плюс `useEffect`
  на состояния репитеров и словарных пикеров — они нативное событие не порождают.
- Визуал: янтарная рамка + `(!)` + строка «Без этого проект не отправится на модерацию».
  Секции (`sec-about`, `sec-tiers`, `sec-placements`) подсвечиваются на уровне оболочки,
  так как это не `Field`.

⚠️ Токен `--warn` `#f59e0b` как **цвет текста** даёт ~2.2:1 и не проходит 4.5:1.
Используется `bg-warn/10` + `text-amber-700`. Та же правка внесена в старый бейдж чеклиста.

## 4. Страница /for-creators

- `src/lib/creator-guide.ts` — манифест: шаги → поля → `{labelKey, descKey, exampleKey,
  tier, completenessKey}`. Подписи полей **переиспользуют** существующие `projectForm.*`,
  а не дублируются.
- `src/app/for-creators/page.tsx` — серверный компонент. Весь `t()` резолвится на сервере,
  в клиентский аккордеон уходят готовые строки: иначе на страницу приехал бы 176-килобайтный
  чанк словаря, который убирали 31.07.
- `src/components/ui/disclosure-list.tsx` — аккордеон (несколько открытых, «раскрыть всё»,
  авто-раскрытие по хэшу `#f-<id>` — поддержка может дать ссылку прямо на пункт).
- `src/lib/creator-guide.guard.test.ts` — сторож. Читает `BLOCKS_PUBLISH` и полный список
  `CompletenessKey` **в рантайме**, а не копией, поэтому новое поле в чеклисте валит тест,
  пока его не опишут на странице.

⚠️ **Жёсткий id проекта-примера непереносим.** Агент зашил `EXAMPLE_PROJECT_ID = 3`;
на проде «Վալդակար» = 18, локально = 34, а в старом наборе данных был 3. Отказ тихий —
`getProject` вернул бы `null` и секция просто исчезла бы. Переделано на поиск по названию.

⚠️ **`proxy.ts` уводил вошедшего создателя с `/for-creators` на `/account`** — member
confinement. Лечится добавлением префикса в `MEMBER_ALLOWED_PUBLIC_PREFIXES`
(`src/lib/auth/member-paths.ts`). Тот же корень, что у бага с `/reports` (21.07): **любая
новая публичная страница, адресованная членам, требует этой правки.**

Ссылки на гид: `/how-it-works` (в колонке создателей не было ни одной кнопки),
карточка «Подать проект» в кабинете, шапка формы подачи (в новой вкладке — чтобы не
потерять полузаполненную форму).

## 5. Цена пакета «по запросу» + две регрессии ранжирования

`SponsorshipTier.priceAmd` был `NOT NULL`, а редактор сводил пустое поле к `0` — пакет,
который никто не оценил, показывался брендам как «0 ֏», то есть бесплатный. Приведено
к контракту плейсмента: `Int?`, `null` → «по запросу».

⚠️ Попутно найдены две живые ошибки: `Math.min` приводит `null` к нулю, поэтому проект
с одним неоценённым пакетом выглядел **бесплатным** и вставал первым как самый дешёвый —
в таблице сравнения избранного (`src/lib/data/brand-favorites.ts`) и в блоке «Рекомендуем
вам» (`src/lib/data/brand-dashboard.ts`). Обе точки теперь отбрасывают неоценённые пакеты
до вычисления минимума.

## 6. Мёртвые колонки и таймлайн

Удалены `Project.language`, `Project.boxOfficeAmd`, `Project.streamingSource` — ни одна
не достижима из формы, на проде все три пусты (проверено дважды, построчно). Заодно
вычищен остаток языкового фильтра в каталоге и в брендовом поиске: контрол убрали 27.07,
а логика осталась и читала колонку. Справочник `StreamingSource` и поле `platforms`
не тронуты.

График производства открыт создателю. ⚠️ При этом обнаружилось, что серверный экшен
создателя `milestonesRows` вообще не читал — открытая секция молча теряла бы этапы;
`parseMilestoneRows` добавлен в оба пути создателя, edit-страница загружает реальные строки.

Чеклист «Что увидит бренд» дополнен: `countries`, `castPhotos`, `placementPricing` и
`translations`. Последний важен: название/синопсис/логлайн требуют лишь одного языка,
поэтому проект может быть только на армянском, а англоязычному бренду покажут армянский.
На проде **ни один** из 8 проектов не заполнен на всех трёх языках.

## Порядок выкатки — обратный обычному

⚠️ **Правило «миграция до push» верно для ДОБАВЛЕНИЯ колонки. При УДАЛЕНИИ — наоборот.**
Живой Prisma-клиент перечисляет колонки в `SELECT` поимённо, поэтому дроп до выкатки
уронил бы прод немедленно. Применённый порядок:

1. Бэкап затронутых таблиц → `docs/prod-migrations/backups/2026-08-04-pre-migration.json`
   (mysqldump на машине нет — выгрузка `Project` + `SponsorshipTier` через Prisma).
2. `ALTER TABLE SponsorshipTier MODIFY priceAmd INT NULL` — совместимо со старым кодом.
3. `git push` → выкатка (~120 с), проверка отпечатка чанков.
4. `UPDATE SponsorshipTier SET priceAmd = NULL WHERE priceAmd = 0` (2 строки).
5. `ALTER TABLE Project DROP COLUMN language, boxOfficeAmd, streamingSource`.

Проверка после: дропнутых колонок 0, обе цены `NULL`, все публичные страницы 200,
на «Վալդակար» — «Գինը՝ հարցումով» вместо «0 ֏».

⚠️ Сразу после миграции проект ещё показывал «0 ֏» — витринный `unstable_cache` на 300 с,
прогретый до миграции. Сам очистился за 240 с, код был в порядке. **Не спешить чинить
то, что чинится истечением кэша.**

⚠️ `sharp` побился на машине и трижды ронял билд на `/opengraph-image`
(`colourspace: parameter space not set`). Лечится `npm rebuild sharp` **плюс** `rm -rf .next` —
одного rebuild мало, кэш держит отравленный артефакт. package-lock не трогали.

## ⏳ Открыто — контент, не код

Прод построчно: **все восемь живых проектов уже не проходят публикационный шлюз**,
и это условие существовало **до** этого релиза.

| 23 | 11 - 2 | 0 | 0 | 0 | | | |

| 25 | Վերջին հոդված | 1 | 0 | 0 | ✗ | ✗ | ✗ |

Шлюз требует минимум один пакет **с непустым списком бенефитов** — этому не удовлетворяет
ни один проект. Значит контент заливали скриптом мимо формы. Практический смысл: правка
или переодобрение любого проекта каталога упрётся в отказ, и упрётся оно в пакеты, а не в
наши новые требования. Пока пакеты не заведены, брендам физически нечего покупать.

Оба пакета, что есть, называются «Official Sponser» (с опечаткой) и пусты.
